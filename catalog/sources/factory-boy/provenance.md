## Environment and dependency remediation

The source uses `setup.py` plus `setup.cfg`, with setuptools as the build
backend and `Faker>=0.7.0` as its runtime dependency. An initial raw-host
`python3` install failed because that interpreter was CPython 3.14 without
pip/setuptools. This was an environment probe failure. Re-running with the
pinned repository uv Python 3.12.11 environment and the hash-locked target
dependency site built and installed `factory-boy==3.3.4.dev0` successfully.

The private lock was generated by `uv pip compile --python-version 3.12
--generate-hashes` and contains Faker 37.1.0, tzdata 2026.3, pytest 8.3.5,
iniconfig 2.3.0, packaging 26.3, pluggy 1.6.0, setuptools 80.10.2, and
wheel 0.45.1. The compiler installs this closure at image build time with
`--require-hashes`; Agent and verifier phases use `no-network`.

## Test inventory and adaptation

With the frozen source installed into a task-local candidate site, the
upstream-compatible probe collected 329 tests and passed 314, with 18 skips
and no failures. ORM integration modules are skipped when optional frameworks
are absent. The production denominator is a separate 30-leaf custom JSON
contract for deterministic JSON-safe core behavior. It covers factory class
creation, declaration resolution, nested overrides, strategies, fuzzy values,
random state, Faker, and utility behavior. It does not claim the skipped
ORM/database suite as part of the denominator.

## Boundary

The private verifier is a `custom-json-v1` bundle. Its root process never
imports candidate code; each scenario is sent to
`nl2repobench.verification.candidate_client.execute_script`, which starts a
UID-10001 child with bounded output, CPU, memory, file, process, storage, and
cumulative wall-clock limits. The root owns the leaf report, collection, JUnit,
grading, and reward. Oracle source bytes are fetched only by the private
Oracle `solve.sh` after it verifies the exact revision and archive digest.
