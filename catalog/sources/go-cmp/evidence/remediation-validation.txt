3. Verifier-strength remediation (why the bundle changed)
- The previous contract covered 11 assertions over 6 bridge operations, so a candidate
  could no-op `Ignore`, `FilterPath`, `FilterValues`, `Transformer`, `Comparer`,
  `Exporter`, `EquateErrors`, `EquateApproxTime`, and `EquateComparable` and still earn
  reward 1.0. That is a one-directional instruction/test gap, so the private contract and
  the typed bridge were extended to 38 assertions over 16 operations covering every
  documented API, including the unfiltered-`Ignore` panic policy and the negative-margin
  panic policy of `EquateApprox`/`EquateApproxTime`.
- New private verifier bundle: sha256:adea29f45f13e3ea4ec9370b3758f733dbf0e374c1710f278943f58b8fc3fcc4
  (2590 bytes, single member contract.sh, mode 0755, deterministic tar/gzip header).
- `instruction.md` was rewritten to match: the `Ignore`/`Exporter`/`AllowUnexported`
  descriptions are now upstream-accurate (previously `Ignore` was described as the
  unexported-field policy), the option semantics of every covered API are stated, Diff is
  documented to name the differing path, and the bridge operation list is the new 16 ops.
  `evidence/traceability.json` maps every documented symbol to its asserting cases and
  every assertion back to its operation.
- Controls were strengthened in the same pass:
  * `background-process.sh` previously produced an empty workspace, so it graded as an
    install failure (0/0) and never proved anything about stray processes. It now builds a
    compiling candidate whose `Equal` leaks a detached `sleep 600` child on every call, plus
    a leaked process from the solve step, so the frozen leaf is collected and failed while
    the verifier must survive and clean up.
  * `forgery.sh` now also overwrites grading.json, junit.xml, and collection.json in
    /logs/verifier on top of reward.json.
  * `hang.sh` uses a real `time.Sleep`, which exercises the supervisor timeout instead of
    tripping Go's deadlock detector.
  * every control shim was extended to declare the enlarged bridge-visible API surface so it
    compiles (a control that fails to build would hide behind the install-failure exception).
- Shared verifier fix (kept in this worktree for integrator review):
  `src/nl2repobench/verification/go_supervisor.py` now always `killpg` the candidate process
  group after the bridge exits, not only on timeout/output-limit. A local probe showed the
  old code left orphaned `sleep 600` children after a clean bridge exit. Because that file is
  inside `GO_RUNTIME_LOCK_FILES`, `toolchain.go.lock.toml` was re-pinned to
  go_runtime_sha256 = sha256:9e4bd0759ce0b95138b7ca0b86aac1c82c33a7509af8fbbfdfc9b0a1fab7cb1f
  and `tests/test_go_adapter.py` passes again (9 passed).
