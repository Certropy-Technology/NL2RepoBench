# Control Plan

The source-owned control scripts are compiled into task-local control bundles.
They are not part of the agent instruction or verifier archive.

| Control | Candidate behavior | Required verifier outcome |
| --- | --- | --- |
| `empty` | Empty `/workspace` | Candidate installation failure and zero reward. |
| `stub` | Installable `fastjsonschema` package whose public calls raise | Fixed collection with low reward. |
| `forgery` | Installable pass-through package that writes forged reward files | Trusted verifier ignores candidate outputs and gives low reward. |
| `install-hang` | Generated by the independent control runner when available | Candidate install timeout, not verifier failure. |
| `call-hang` | Installable package that never completes import | Bounded candidate timeout, fixed collection, and zero reward. |
| `workspace-invalid` | Workspace symlink escaping to `/etc/passwd` | Workspace-copy rejection, not verifier failure. |

All listed controls have source-owned scripts and can be materialized by the
generic compiler from the final production bundle. They exercise the trusted
Oracle/verifier path only and are separate from any model Agent Run.

Release `0.3.1` Harbor evidence is under `.nl2repo/authoring-work/r3-jobs/`.
Empty, stub, forgery, install-hang, call-hang, and workspace-invalid all
produced `valid=true`, reward `0.0`, and a verifier network probe with no public
connectivity. Stub, forgery, and call-hang retained the frozen 2,899-leaf
collection with zero passes. Empty and install-hang produced
`candidate-installation-failed`; workspace-invalid produced
`candidate-workspace-rejected`. The forgery candidate wrote untrusted reward
files, but the trusted verifier still reported zero reward. No model Agent Run
was started by this lane.
