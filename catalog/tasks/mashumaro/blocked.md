## Generated dataclass serialization surface

Mashumaro does not implement a single stateless JSON transformation. It adds
serialization methods to Python dataclass hierarchies by generating Python
source and executing it during subclass setup, lazy first use, or codec
construction. `CodeBuilder.compile()` calls `exec`; generated helper names may
contain UUID-derived values, and generated methods retain live type, class,
config, dialect, and callback objects in process-local globals.

The root package exports `DataClassDictMixin`, `MissingField`, `field_options`,
and `pass_through`. The principal generated API and format mixins are:

- `DataClassDictMixin.to_dict(...)` and `from_dict(...)`;
- `DataClassJSONMixin.to_json(...)` and `from_json(...)` using stdlib JSON by
  default;
- `DataClassORJSONMixin.to_jsonb(...)`, `to_json(...)`, and `from_json(...)`;
- `DataClassMessagePackMixin.to_msgpack(...)` and `from_msgpack(...)`;
- `DataClassYAMLMixin.to_yaml(...)` and `from_yaml(...)`;
- `DataClassTOMLMixin.to_toml(...)` and `from_toml(...)`.

Generated signatures depend on class configuration. A representative source
probe observed a plain class with `to_dict(self)` and
`from_dict(d, *, dialect=None)`. A class enabling omit-none, alias, dialect,
and serialization-context generation had:

```text
to_dict(self, *, omit_none=False, by_alias=False, dialect=None, context=None)
from_dict(d, *, dialect=None)
```

Both classes received private `__mashumaro_to_dict__` and
`__mashumaro_from_dict__` methods. A basic probe converted an integer string
and ISO date into a typed dataclass and serialized the date back to an ISO
string. This is behavior evidence, not an implementation prescription.

Configuration and extension behavior includes:

- field and global aliases, alias-only input, omit-none/default, key sorting,
  extra-key rejection, named-tuple modes, and lazy compilation;
- optional generated `omit_none`, `by_alias`, `dialect`, and `context`
  parameters;
- pre/post serialize and deserialize hooks, including inherited hooks and
  hooks carrying mutable context;
- callable or `SerializationStrategy` field/global converters, subclass
  matching, `SerializableType`, `GenericSerializableType`, and pass-through
  strategies;
- class hierarchies and discriminated unions with optional callable variant
  taggers;
- generics, PEP 695 aliases, recursive/self references, `Annotated`,
  `Literal`, `TypedDict`, named tuples, enums, `NewType`, and type variables;
- native values including date/time/timezone, UUID, Decimal, Fraction,
  pathlib/path-like values, regex patterns, IP values, bytes, tuples, sets,
  deques, mappings, and user-defined dataclasses; and
- rich exceptions that retain field names, live field/holder types, bad
  values, extra-key sets, discriminator details, and chained causes.

The public supporting surface includes `BaseConfig` and its generation
constants, `Dialect.merge`, `SerializableType`, `GenericSerializableType`,
`SerializationStrategy`, `RoundedDecimal`, `Discriminator`, `Alias`, 13
exception classes, and a substantial type/helper layer. Upstream tests also
directly import `mashumaro.core.meta` internals, construct `CodeBuilder`, patch
generation methods, and assert private generated method naming. Those tests
are implementation coverage, not automatically a suitable public task API.

## Codecs and JSON Schema

The reusable codec classes generate per-shape encoder/decoder methods from a
live Python `shape_type`:

| Module | Encoder/decoder | Default encoded form | Dependency |
| --- | --- | --- | --- |
| `codecs.basic` | `BasicEncoder`, `BasicDecoder` | arbitrary Python basic form | runtime only |
| `codecs.json` | `JSONEncoder`, `JSONDecoder` | JSON `str` | stdlib `json` |
| `codecs.orjson` | `ORJSONEncoder`, `ORJSONDecoder` | JSON `bytes` | `orjson` |
| `codecs.msgpack` | `MessagePackEncoder`, `MessagePackDecoder` | MessagePack `bytes` | `msgpack` |
| `codecs.yaml` | `YAMLEncoder`, `YAMLDecoder` | YAML `str`/`bytes` | `PyYAML` |
| `codecs.toml` | `TOMLEncoder`, `TOMLDecoder` | TOML `str` | `tomli-w`, plus `tomli` below 3.11 |

Each module also exposes functional encode/decode aliases. Basic/JSON/YAML/
MessagePack codecs accept custom pre-decode or post-encode callables;
format-specific dialects preserve values such as bytes, datetime objects, and
UUIDs for the backend. Codec instances retain their generated method and type
state.

The JSON Schema root exports `build_json_schema`, `JSONSchemaBuilder`,
`DRAFT_2020_12`, and `OPEN_API_3_1`. It also exposes schema model dataclasses,
constraint annotations, dialects, a mutable builder context/definitions map,
and plugin callbacks. If `orjson` is importable, JSON Schema models select the
ORJSON mixin; otherwise they fall back to the stdlib JSON mixin. Optional
dependency presence therefore changes an actual package code path, not just a
test skip. There is no console-script entry point or project CLI.

## Separate-verifier and JSON child-adapter analysis

The repository's generic Python `candidate_client.call` contract sends one
JSON object containing `module`, `attribute`, JSON `args`, and JSON `kwargs`.
It starts a fresh isolated candidate process for each call. The child imports
the attribute, invokes it once, and JSON-encodes either one result or only the
exception type/message. It does not preserve object handles or state between
calls.

That contract cannot preserve the frozen mashumaro behavior:

1. `DataClassDictMixin` works by being inherited by dynamically declared
   dataclasses. The class definitions, field annotations, defaults,
   inheritance, descriptors, and live target type cannot be sent as ordinary
   JSON arguments.
2. Every codec constructor requires a live `shape_type`, often a nested
   generic, union, `TypedDict`, named tuple, enum, or recursive class. A type
   object cannot cross the generic request boundary.
3. Hooks, field converters, serialization strategies, discriminator taggers,
   custom JSON/YAML/MessagePack functions, and JSON Schema plugins are live
   callables. Their annotations and closure/class state are observable.
4. Generated methods, lazy compilation, subclass discovery, recursive types,
   builder contexts, and codec instances require several operations in the
   same process. A fresh process per generic call changes those semantics.
5. Results include dataclass instances, dates, UUIDs, decimals, enums,
   path-like values, sets, tuples, non-string-key mappings, and exceptions with
   rich attributes/causes. Binary ORJSON and MessagePack output is `bytes`.
   The generic child cannot JSON-encode these values without losing type or
   failing.
6. The upstream suite patches generation internals, inspects helper/type
   objects and private method names, and checks debug/generated-code behavior.
   Directly importing candidate modules into trusted pytest to retain these
   assertions would violate the required verifier boundary.

A production conversion needs a reviewed mashumaro-specific child scenario
adapter. At minimum, its JSON schema would need to:

- declare dataclasses, inheritance, recursive/generic type expressions,
  fields, defaults, metadata, configs, dialects, and discriminators from a
  closed grammar;
- instantiate allowlisted hook/converter/strategy/plugin recipes inside the
  candidate child, without executing trusted-test callbacks in that process;
- keep class creation, generated methods, codec objects, state transitions,
  and all scenario operations in one bounded child session;
- encode non-JSON values with validated type tags, use base64 for binary codec
  results, preserve ordered mappings, and canonicalize set-valued observations;
- return structured exception fields and cause/context trees, not only a
  flattened message; and
- expose generated-code/internal observations only for assertions explicitly
  retained in a reviewed public contract.

That adapter is a material task/API design decision. It was not approved or
implemented in this screening lane. A narrowed JSON-safe task would likewise
be a new reviewed contract and could not claim full upstream parity merely by
dropping difficult assertions.

## Blocking findings and reopen conditions

Keep `mashumaro` **blocked** and do not create a declarative task source or run
Oracle from this record. The blockers are:

1. The requested commit is a post-`v3.22` snapshot that still reports version
   `3.22`; registry source/wheels with that version are different and cannot
   substitute for the exact archive.
2. There is no hash-locked build/runtime/test closure, offline wheelhouse,
   immutable image, or approved policy for native codec/third-party feature
   dependencies.
3. Collection depends on the selected Python and dependency set. A final
   interpreter, plugin policy, node list, denominator, and skipped-test metric
   contract are not frozen.
4. The generated class/type/callable/stateful/binary behavior does not fit the
   generic stateless JSON candidate call, and no reviewed task-specific child
   adapter exists.
5. No private test/command artifact, Oracle bundle, final verifier, control
   record, review approval, or contamination/network policy is authorized.

Reopen only after the exact commit archive is materialized through the
authorized artifact path; a platform-specific offline dependency bundle and
final image are pinned; collection is repeated in that image with structured
status/metric semantics; a child-side scenario adapter and assertion mapping
are reviewed; and private tests, command plan, and Oracle references are
provisioned outside the public catalog. Three valid Oracle runs and the
empty/stub/forgery/offline controls belong to that later execution stage.
