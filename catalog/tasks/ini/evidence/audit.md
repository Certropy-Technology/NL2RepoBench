## JSON-Safe API Scope

The exact CommonJS root object has these direct callable exports:

```text
parse, decode, stringify, encode, safe, unsafe
```

The recommended first scope is `parse` and `stringify`, with the aliases and
escaping helpers included only if a later instruction explicitly maps and
tests them. The current generic child boundary can call a literal export name
from package `ini`; it must not accept arbitrary package names, paths, loaders,
or candidate-controlled options outside the fixed operation schemas.

### `parse` / `decode`

Use `parse(text, options?)` where:

- `text` is a bounded UTF-8 string;
- `options`, when present, is an object containing only the boolean
  `bracketedArray` option; and
- the result is limited to JSON values: `null`, booleans, strings, finite
  numbers if a future source revision adds them, arrays, and string-keyed
  objects.

For this revision, ordinary unquoted values remain strings except the exact
tokens `true`, `false`, and `null`, which decode to their JSON primitive
values. Sections become nested objects. Repeated `[]` keys become arrays when
`bracketedArray` is enabled; repeated keys become arrays when it is disabled.
Comments, blank lines, escaped separators, quoted values, nested section names,
and CRLF input are part of the observed parser behavior.

The implementation intentionally ignores `__proto__` assignments and does not
attach a `__proto__` section. That prototype-safety behavior should be covered
by a future child-side test, but null-prototype identity itself is not a JSON
wire value and must not be scored through ordinary parent-process imports.

### `stringify` / `encode`

Use `stringify(value, options?)` where `value` is recursively composed only of
JSON-safe values: `null`, booleans, finite numbers, strings, arrays, and plain
objects with string keys. Exclude `undefined`, non-finite numbers, `BigInt`,
symbols, functions, dates, regular expressions, class instances, custom
prototypes, `toJSON` methods, and cycles.

The JSON options object may contain only these documented fields:

```text
align, bracketedArray, newline, platform, section, sort, whitespace
```

`section` is a string. `platform` should be explicitly restricted to `linux`
or `win32` so line endings are deterministic; the default process platform
must not become an unstated host dependency. The legacy string form
`stringify(value, "section")` is JSON-safe but should be included only if it is
explicitly specified and tested. The result is a bounded string using LF or
CRLF according to the reviewed platform option. Object key ordering is
preserved unless `sort` is true; nested sections, array bracket suffixes,
alignment, whitespace, and section blank-line behavior follow the pinned
source implementation.

`safe` and `unsafe` are pure string-to-string helpers and could cross the same
boundary, but they are not part of the recommended primary parse/stringify
scope until their quoting and comment-escape edge cases have their own
traceability entries.

### Boundary Exclusions

The task must not claim full `ini` parity for filesystem/CLI behavior, package
metadata, process mutation, platform discovery, arbitrary JavaScript values,
or object-prototype identity. Request and response sizes must remain within
the child boundary limits. Error assertions should use only a reviewed
exception type/message projection; the generic runner does not expose custom
error fields.
